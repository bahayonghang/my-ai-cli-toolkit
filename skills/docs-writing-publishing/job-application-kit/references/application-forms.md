# Application Forms（网申表单字段）

JD/门户要求自由文本字段时触发：自我介绍段、结构化项目条目、硬字符限制 pitch、动机题、字数受限的胜任力题。产物不编译，是用户直接粘贴的文本。

## 总纲

**表单里的每条 claim 必须已被简历与求职信的同一组三事实源支撑。** 表单是"从已为真的内容里选取并按问题重排"，不是引入新主张、夸大范围或凑字数的地方。writing-style 与 resume-writing 的全部准确性规则在此原样适用。

## 字段类型一：自我介绍段（100-200 词）

结构：
1. 当前状态（在做什么 / 在读什么）
2. 最强的一条证据，带数字与规模
3. 一句轨迹线（转行或特殊经历确实有趣时才写）
4. 下一步想要什么，连接到这家雇主的真实业务

规则：
- **最强证据先行，不按时间序**
- 按角色类型各写一版（投后端岗与数据岗的自我介绍是两段话），标注各自去向
- 末句绑定该雇主；通用自我介绍一眼即穿
- **程序化计数词数并报数**——门户会静默截断；附裁剪变体并指明先删哪句

## 字段类型二：结构化项目条目（名称 / 角色 / 起止 / 描述）

- **项目名 ≠ 雇主名**："仓储库存预测平台"是项目，"Acme Corp"是雇主。客户比雇主有名时只在关系真实（驻场交付等）时写客户
- **Role 是该项目中的角色，不得升格为职位头衔**
- **日期是项目起止，可与雇佣期不同**（更准确且规避低产出误读）；只有用户说得出真实起点才能缩窄，禁止为了比例好看编造边界
- 描述 100-150 词：系统做了什么、谁在用 → 最难的技术问题及解法 → 带数字的结果。另备 ~60 词短版
- **Scope discipline 比 CV 更严**：署名条目默认读作整体所有权；参与而非主导必须在描述内言明

## 字段类型三：硬字符限制 pitch

- 具体情境胜过形容词（大多数人交形容词，具体情境天然突出）
- 方法：选最独特且真实的一点（一个数字 / 罕见背景组合 / 与雇主问题同构的问题形状）→ 起草 4-6 个不同角度 → **程序化计字符数不许估算** → 全部呈现附计数，推荐一个并说明理由
- 优先能把候选人的问题映射到雇主问题的真实版本

## 输出格式

每个雇主一个 `.txt` 存入 `career/outputs/`，含：
- 雇主名与覆盖岗位的头部说明
- 每个字段带标签 + 实测词数/字符数 + 短变体
- `NOTE TO SELF` 块：范围提醒与内容可能引出的问题的准备答案，**明确标注不可粘贴**
- 日期速查表（保证各处日期字段一致，不必重新推导）

## 交接前验证

- [ ] 每条事实 claim 可溯源到三事实源联合
- [ ] 与同一岗位已提交的 CV/求职信零矛盾
- [ ] 参与性工作的所有权正确限定
- [ ] 词数/字符数为实测值
- [ ] 在读资格写明 in progress
