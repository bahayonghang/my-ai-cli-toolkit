# Profile Schema（用户档案约定）

`career/` 是本套件的全部事实来源。三个事实文件缺一不可；产物中的每条事实性 claim 必须至少被其中一个支持。

## career/profile.md（结构化档案）

```markdown
# 求职档案

## 身份
- 姓名 / 城市 / 国家 / 通勤约束：
- 状态：（在职 / 离职 / 在读）
- LinkedIn headline：

## 语言表          <!-- Language Gate 的输入，必须显式维护 -->
| 语言 | 等级 | 依据 |
|------|------|------|
| （只写真正能工作的语言；未声明的语言在评估中按硬排除处理） |

- CV 语言：（简历固定使用哪种语言写，不随单个 JD 切换）

## 教育
- 学位 / 领域 / 起止年月 / 院校 / 论文或方向
- （在读学历必须显式标注 "在读，预计 YYYY-MM 完成"，裸年份区间视为已完结）

## 工作经历        <!-- 倒序；每段含职责与可量化成就 -->
- 职位（起止）— 公司（地点）
  - 成就要点…

## 技能
- 主力 / 次要 / 领域 / 工具链

## 认证 · 发表 · 获奖

## 目标与动机
- 目标职位类型、目标行业、加分项（如育儿假政策、不 on-call）
- 什么任务让你有能量 / 消耗你

## 硬约束（deal-breakers）
- （地点、薪资底线、签证/公民身份状态等；语言要求写在语言表，勿在此重复）
```

## career/behavioral.md（行为画像）

- 核心行为特质表（正式测评 PI/DISC/MBTI 结果，或自评综合）
- **成长区用积极框架存储**：直接写成"如何在申请中正面表述"
- **JD 关键词双向映射**：目标岗位常见关键词 → 强匹配行为 / 潜在摩擦点（摩擦点标注"非一票否决"）
- 有效 / 无效的管理风格偏好
- 用途：求职信语气校准、审稿阶段的 voice check、STAR 选择。禁止过度声称。

## career/master-cv.md（母版简历）

全量真实经历与成就的完整版，不做裁剪。它是 W1/W2 的裁剪事实源：定制版简历上的每条经历都必须能在母版中找到原型。历史定制稿（outputs/）只能作措辞参考，**不能**作为事实来源——漂移过的旧草稿不为其自身准确性背书。

## 写入协议（read-before-write）

对 career/ 下任何文件的更新遵循双桶合并：

1. 先完整读取现有内容再动笔；重跑不得重复提议已有条目。
2. 变更分两桶：
   - **Additive**（全新内容）：整批列出 → 用户一次性确认（可点名跳过某几条）→ 写入。
   - **Conflicting**（与既有内容冲突）：逐条列出冲突双方 → 用户裁决 `[保留旧] / [替换] / [手动处理]` 后才动笔。
3. 定向 Edit，不整文件重写。
4. 推断性新增必须带来源标注：`*(GitHub — repo 名)*`、`*[由对话推断，使用前请复核]*`。无标注的推断内容视为污染。

## 会话内事实回写（不变量 1 的执行细则）

任何工作流中，用户确认、纠正或补充的事实（一个数字、一个项目细节、一项技能、一次范围澄清）必须在**同一轮**写入 `career/profile.md` 对应小节。只存在于对话里的事实会被后续会话按无支撑内容剔除——真实的成就会静默消失。若新事实修正了 master-cv 或 behavioral 中的既有记载，两处同步修正。
