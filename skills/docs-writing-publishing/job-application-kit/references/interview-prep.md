# Interview Prep（面试准备）

W4 执行。核心原则：`/apply` 优化公司**读到**什么，本工作流优化公司**听到**什么——两者靠一致性连接。面试官读过你提交的简历与求职信，一切准备必须与那些文件的主张一致。

## Step 1：加载一致性上下文

1. 找到该职位的产出材料（`career/outputs/` 下对应文件）：JD 全文、实际提交的简历与求职信。**这些是面试官读过的版本**，所有 talking point 与其一致。
2. 材料缺失时明确说明缺什么，请用户补 JD 或粘贴材料；不猜测。
3. 向用户确认：轮次（电面/技术/案例/终面）、时间、形式、面试官姓名与职务（如有）。
4. 通读 profile-schema、job-evaluation、writing-style 三份参考，后续步骤不重读。

## Step 2：公司调研（面试向）

按 web-research.md 执行：缓存优先 → 缺失/过期则全新调研 → 回写缓存 → 进入 prep pack 的每条 claim 独立核实。

面试追加两项：
- **面试官角度**：仅查公开职业信息，推测其提问角度（hiring manager 探团队契合；资深工程师探技术深度；HR 探履历时间线），不做超出公开信息的猜测
- **对话钩子**：2-3 个近期的、可核实的公司具体事实（产品发布、公开的战略优先级），供"为什么这家公司"环节自然引用

## Step 3：组装 Prep Pack

存为 `career/outputs/interview_prep_<轮次>.md`（每轮一份，留作历史）并在对话中呈现。六个小节：

### 1. 预测问题（优先级严格递减）
1. **早期轮次的记录反馈**——被质疑过、悬而未决的点一定会回来
2. **Fit 评估的缺口**——档案最弱处就是最可能被探处；每个缺口备诚实桥接答案（承认 → 相邻经验 → 学习路径）。**永不准备编造经历的答案**
3. **JD 明示要求**——逐项 competency 过一遍
4. **轮次类型**——电面问动机与时间线；技术面问 JD 技术栈；终面问价值观、薪资、"你还有什么顾虑"

### 2. STAR 映射
- 用 behavioral/profile 中现成的 STAR 素材按"适用问题"标签匹配
- 无素材覆盖的预测题：**只把三事实源中的事实排布成 S/T/A/R**，不加料；新写的 STAR 经用户明确同意后才回写 profile
- 档案中未填完的 STAR 占位要提醒用户在面试前补齐

### 3. 一致性清单（Consistency Brief）
列出提交材料中最可能被追问的具体主张（成就、数字、技能强调）。规则一句话：**纸面上没有的主张房间里也不能说，纸面上有的每一条都要经得起深挖。**

### 4. 定制难题
"为什么离开上一家"（向前看，不贬损前雇主）、"你没有 X 经验"（承认→相邻经验→学习路径）、"为什么是这家公司"（必须用 Step 2 的已核实钩子，禁用通用答案）等，逐题给出针对本岗位的答案要点。

### 5. 反问清单
按轮次选 4-6 个：电面问角色与团队；技术面问技术栈与成长；终面问文化与领导力（这是发现 deal-breaker 的最后机会）。调研已能公开回答的问题删掉——问了显得没做功课。

### 6. Logistics
形式对应的实操提示（电话/视频注意事项）+ 时间与面试官名单头部。

## Step 4：模拟面试（可选）

用户同意后在对话内进行：
1. 先易后难：自我介绍 → 岗位技术题 → 1-2 道 JD competency 行为题 → 一道难题或 curveball
2. 每个回答后给简短反馈：哪里有效、哪里要收紧、哪个 STAR 会更好
3. 反馈对齐 behavioral.md 的自然语域，校准到本人风格而非通用理想模板

## 收尾

提醒：面试结束后把该轮反馈与新事实写回 `career/profile.md`（prep 是新事实最高产的场合——只存在于 prep 文件里的事实同样会被后续起草当作无支撑剔除）。

## 硬边界

1. 与提交材料零矛盾；不教唆超出纸面的主张
2. 缺口只做桥接答案，永不编造经历
3. 只用已核实的研究；面试官信息限于公开职业资料
4. 写入范围：prep pack 文件 + （经同意）profile 的 STAR/事实更新；框架参考文件不改
