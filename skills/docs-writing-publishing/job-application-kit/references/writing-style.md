# Writing Style（表述风格与包装边界）

W1 起草与 W3 包装共用。W3 只做本文允许的事：重排、量化、换框架、动词强化——不引入三事实源之外的新事实。

## 硬规则

1. **不用破折号（em-dash / "——"）。** 用逗号、句号或重组句子。
2. **不用陈词滥调与填充短语。** 删掉："我热爱""我相信我能胜任""发挥我的技能""快速上手""创造协同"。
3. **空泛标签必须有具体支撑。** 每个主张背后要有一个具体例子或事实。
4. **不用道歉式、过度谦卑的语言。** 不写"我觉得我或许能贡献"，写"我能带来 X，证据是 Y"。
5. **公司主张一律先核实**（见 web-research.md）。
6. **只调强调，不动实质——interview backtrack test 三档判定：**
   - **OK**：把最相关的经历排到前面；用目标领域的自然同义词；突出宽泛职责中的一个侧面。
   - **Flag**：把学术 + 业界经历合并成一句暗示全是业界的话；用 JD 的专有术语描述实际相邻但不相同的工作。
   - **Never**：声称没有的经历；暗示没待过的领域。
   - Flag 区的 bullet 起草后向用户呈现："这句是 stretch 因为 X。保留、弱化还是删除？"

## 语气基调

- 温和而直接；自信不傲慢。会话式专业，不端着也不随意。
- 第一人称 + 主动语态："我搭建了"，不是"该系统由本人负责开发"。
- **展示而非宣称**：不写"我是团队合作者"，写一个具体的协作例子及其结果。
- 语气与 `career/behavioral.md` 的自然语域对齐：协作者型画像不该配好斗的英雄叙事；说服者型画像不该配过度对冲的措辞。

## 标题/邮件主题公式

**[头衔或学历] + [JD 中的相关关键词]**，如"机器学习工程师 · MLOps 平台落地"。禁用"XX 岗位申请"这类通用标题。

## 扫描友好结构

- 小标题反映内容实质，自然嵌入行业关键词
- 删除一切填充语言；求职信正文一页为硬上限

## Forward-Looking Framing（求职信核心原则）

求职信不是 CV 复读：
- 围绕"你能替雇主解决哪些任务"展开，而非罗列过去做过什么
- 描述方法、工具与知识，以及雇主雇你会得到什么结果
- 过去的例子只用 1-2 个，作为前瞻主张的证据

## Bullet 风格

- 动词开头，或加粗类别标签起头
- 具体：数字、工具、结果
- 变换句式，不要每条同构

## 按岗位类型的措辞侧重

- 技术/ML 岗：语言、框架、模型架构、数据规模、管道复杂度、独立项目先行
- 领域岗：领域专长与方法论先行，技术作为增强手段
- 咨询/顾问岗：利益相关方沟通、项目协调、技术与业务的桥接
- 管理/资深岗：项目管理、带人、课程/体系建设；高学位作为独立交付能力的证据

## 多语言

默认跟随 JD 语言；非母语信件要写得地道，不是翻译腔。日期格式、落款随当地惯例。
