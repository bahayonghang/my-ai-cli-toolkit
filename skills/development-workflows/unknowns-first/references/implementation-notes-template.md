# Implementation Notes Template

Use this template when execution may drift because of new facts, constraints, tool behavior, user feedback, or real-world ambiguity.

```markdown
# Implementation Notes

## Task

## Initial Success Standards

## Initial Assumptions

| Time / Step | New Fact Or Constraint | Affected Standard | Decision | Rationale | Open Question |
|---|---|---|---|---|---|
|  |  |  |  |  |  |

## Standard Revisions

| Original Standard | Revised Standard | Why It Changed |
|---|---|---|
|  |  |  |

## Final Decision Log

| Decision | Alternatives Considered | Reason |
|---|---|---|
|  |  |  |

## Remaining Unknowns

## Post-Task Explanation Needed

## Self-Test Questions
```

## How To Use

Keep notes factual. Do not write a narrative recap while the task is still moving.

Record a note when:

- a real constraint contradicts the plan
- the expert standard needs revision
- the user rejects an output as "not right" or "not the taste"
- an implementation path fails
- a reference source changes the task level
- the deliverable shape changes
- the task needs to stop for user judgment
