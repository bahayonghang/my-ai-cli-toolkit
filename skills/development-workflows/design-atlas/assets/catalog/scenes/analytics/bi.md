# 企业级 B 端 Web 工作台 UI/UX 设计规范

## 1. 角色与设计目标（Role & Objective）

你是一名具有丰富企业级 SaaS、金融科技和复杂业务系统经验的资深 UI/UX 设计师、Design System 架构师及前端工程师。

请基于现代企业级产品的设计最佳实践，设计或优化一个专业、现代、克制、高信息密度的 B 端 Web 工作台（Enterprise Dashboard）。

**核心设计风格：**

- Light Minimalism：浅色极简主义
- Modern Enterprise SaaS：现代企业级 SaaS 风格
- Card-Based Layout：结构化卡片布局
- Data-Driven Interface：数据驱动型界面
- Information-Dense but Breathable：高信息密度与舒适留白之间的平衡
- Functional Aesthetics：功能优先的精致视觉设计

最终效果应具有成熟商业软件的专业感、统一性和可维护性，而不是单纯追求视觉炫酷的概念稿。

**核心原则：Clarity over Decoration, Function over Ornament, Consistency over Novelty.**

## 2. 信息架构（Information Architecture）

采用任务驱动、层级清晰的信息组织方式。

### 第一层：核心业务概览

页面首屏优先展示最重要的 3–6 个 KPI 指标。

每个指标卡根据业务需要包含：

- 指标名称及必要说明
- 核心数值及单位
- 同比或环比变化
- 变化方向与业务语义
- 可选的微型趋势图（Sparkline）
- 数据更新时间或统计周期

避免所有 KPI 使用相同的视觉权重。根据业务优先级区分主要指标与次要指标。

### 第二层：趋势与分析

通过图表帮助用户理解：

- 当前业务状态
- 历史变化趋势
- 不同维度之间的差异
- 异常变化及潜在风险

优先采用折线图、柱状图、堆叠图等容易理解的可视化方式。

提供必要的时间范围选择、维度切换和图表说明。

### 第三层：业务明细与待办事项

根据业务场景展示：

- 数据表格
- 最近活动
- 待处理任务
- 异常记录
- 业务状态
- 重要事件

表格应支持适当的搜索、排序、筛选、分页及行级操作。

### 第四层：辅助信息与快捷操作

包括：

- 常用功能入口
- 系统通知
- 帮助与文档
- 用户设置
- 次要统计信息

辅助内容不应抢占核心业务区域的视觉注意力。

## 3. 页面布局（Layout System）

采用响应式 CSS Grid 与 Flexbox 构建稳定的页面布局。

### 整体结构

- 左侧：主导航 Sidebar
- 顶部：全局工具栏 Topbar
- 中央：主要工作区域 Main Content
- 可选：上下文侧边栏 Context Panel

推荐桌面端布局参数：

- 展开导航宽度：224–256px
- 折叠导航宽度：64–72px
- 顶部工具栏高度：56–64px
- 主内容边距：24–32px
- 卡片间距：16–24px
- 页面采用 12 列响应式栅格作为布局参考

### 页面节奏

采用清晰的视觉浏览路径：

Page Header → KPI Overview → Analytics → Detailed Data → Secondary Actions

避免所有模块采用相同大小和相同视觉权重。

主要图表可占据 8 列，次要分析或任务模块占据 4 列。

页面应具有明确的内容主次、对齐关系与节奏感。

### 响应式适配

- ≥1440px：完整桌面布局
- 1024–1439px：适度压缩导航与栅格
- 768–1023px：折叠侧边栏，重排卡片
- <768px：单列优先，简化工具栏，保留核心功能

断点可以根据实际内容溢出情况调整，不应机械套用。

对于复杂数据表格，优先保留表格语义，通过横向滚动、列显隐或独立详情视图适配窄屏。

## 4. 视觉设计系统（Visual Design System）

### 色彩体系

采用克制、统一、语义明确的配色方案。

推荐基础色：

| Token | 推荐值 | 用途 |
|---|---|---|
| Primary | #635BDB | 主按钮、选中状态、重点交互 |
| Primary Hover | #5146C5 | 悬停状态 |
| Background | #F7F8FA | 页面背景 |
| Surface | #FFFFFF | 卡片与内容容器 |
| Text Primary | #1F2937 | 标题、关键内容 |
| Text Secondary | #667085 | 描述、辅助内容 |
| Border | #E5E7EB | 轻量边界 |
| Success | #16A34A | 成功、积极变化 |
| Warning | #D97706 | 警告、待处理 |
| Danger | #DC2626 | 错误、高风险 |

颜色必须遵循业务语义。

例如，成本上升未必是积极变化，数值下降也未必是负面变化。

不要仅依赖红绿色区分状态，应同时使用文字、图标或形状辅助表达。

### 字体系统

中文优先使用：

Inter、思源黑体（Noto Sans SC）及系统字体回退方案。

建议字号层级：

- 页面标题：24–28px / Semibold
- 区块标题：16–18px / Semibold
- KPI 数值：28–36px / Semibold
- 正文：14px / Regular
- 辅助文字：12–13px / Regular

对于高密度业务页面，可适当采用 13–14px 正文，但必须保证可读性。

数值展示使用 Tabular Numerals，确保数字变化时宽度稳定。

### 间距系统

采用基于 4px 的间距体系：

4 / 8 / 12 / 16 / 24 / 32 / 48

典型应用：

- 图标与文字：8px
- 表单元素间距：12–16px
- 卡片内部 Padding：20–24px
- 模块间距：24px
- 大型区块间距：32px

避免随机使用不一致的间距。

### 圆角与阴影

采用适度圆角：

- 输入框与按钮：6–8px
- 卡片：10–12px
- 弹窗：12–16px

阴影应轻量、自然。

优先通过背景、留白和边界区分层级，避免厚重阴影、大面积渐变和过度玻璃拟态。

## 5. 卡片组件规范（Card Components）

卡片不是简单的圆角容器，而是具有明确业务语义的内容单元。

每张卡片应围绕一个主题组织信息。

标准卡片可包含：

1. Header：标题、描述、操作入口
2. Content：主要信息或图表
3. Footer：补充说明或次级操作

设计要求：

- 同类卡片保持一致的内边距与标题位置
- 同一行卡片尽量保持视觉高度协调
- 不要为了统一高度制造大量无意义空白
- 避免卡片内部再次嵌套大量卡片
- 不要将所有信息都包裹在独立卡片中
- 数据密集区域允许使用连续表格或分组容器

通过层级、排版和空间关系建立高级感，而不是依赖装饰性元素。

## 6. 数据可视化（Data Visualization）

图表必须服务于业务分析与决策。

### 图表选型

- Line Chart：连续趋势
- Bar Chart：分类比较
- Stacked Bar：组成与变化
- Donut Chart：少量分类的占比
- Table：精确数据及明细
- Sparkline：紧凑型趋势概览

避免使用 3D 图表、无意义的动画或过度装饰性图形。

### 图表视觉规范

- 图表配色与全局 Design Tokens 保持一致
- 网格线采用低对比度中性色
- 坐标轴、单位、时间范围清晰
- Tooltip 展示准确数值与必要上下文
- 图例顺序与图表顺序一致
- 避免无依据截断坐标轴造成误导
- 数值格式、百分比、小数位保持统一
- 数据缺失、异常和延迟必须明确标识

### 图表交互

根据业务需要提供：

- 时间范围切换
- 指标维度选择
- Tooltip
- Legend Toggle
- Drill-down 下钻
- 数据刷新
- 数据导出

交互应具有明确反馈，不应为了动态效果而增加不必要的操作成本。

## 7. 表格与复杂数据交互（Data Table UX）

B 端系统应优先保证数据操作效率。

表格设计要求：

- 表头清晰，字段命名准确
- 数值列右对齐，文本列通常左对齐
- 金额、日期、百分比采用一致格式
- 支持必要的排序、筛选与搜索
- 对长文本提供截断及完整内容查看
- 状态使用语义标签，而非单纯颜色
- 批量操作应在选中记录后清晰出现
- 重要操作提供确认与结果反馈
- 大数据量场景根据需求使用服务端分页或虚拟滚动

提供可选的信息密度模式：

- Comfortable：舒适
- Default：标准
- Compact：紧凑

避免通过无限缩小字号实现高信息密度。

## 8. 交互设计（Interaction Design）

所有可交互元素都必须具备明确、完整的状态反馈。

至少考虑：

- Default
- Hover
- Active
- Focus
- Disabled
- Loading
- Empty
- Error
- Success

交互要求：

- 导航状态清晰
- 按钮反馈及时
- 筛选条件可见且可重置
- 异步操作提供 Loading 状态
- 数据为空时提供有意义的 Empty State
- 请求失败时提供错误说明和重试入口
- 危险操作采用适当的二次确认
- 复杂操作允许撤销或恢复（适用时）
- 避免不必要的弹窗打断用户工作流程

动效建议采用 120–240ms 的轻量过渡，具体根据交互类型调整。

尊重系统 Reduced Motion 设置。

## 9. 无障碍与易用性（Accessibility）

以 WCAG 2.2 AA 作为设计目标。

要求：

- 普通文字对比度至少 4.5:1
- 大号文字对比度至少 3:1
- 必要的非文本 UI 元素满足 3:1 对比度要求
- 所有主要功能支持键盘操作
- 焦点状态清晰可见
- 表单具有明确标签和错误提示
- 图表提供必要的文字摘要或数据替代形式
- 图标按钮具有可访问名称
- 不仅通过颜色表达状态
- 点击目标符合 WCAG 2.2 对目标尺寸或间距的要求

## 10. 组件与工程实现（Component Architecture）

优先构建可复用、可扩展的设计系统，而不是一次性的静态页面。

建议组件划分：

- AppShell
- Sidebar
- Topbar
- PageHeader
- KPIStatCard
- AnalyticsCard
- ChartContainer
- DataTable
- FilterBar
- StatusBadge
- ActivityFeed
- QuickActions
- EmptyState
- ErrorState
- LoadingSkeleton

实现要求：

- 使用语义化 HTML
- 采用 CSS Variables 或主题 Token
- 保持组件职责单一
- 避免重复样式与魔法数字
- 支持主题扩展
- 兼顾性能与可维护性
- 尽量复用项目现有技术栈及组件库
- 不要为了视觉效果引入大量额外依赖
- 对复杂图表和大型表格考虑渲染性能
- 确保页面不存在不必要的布局抖动

如果是已有项目，应优先遵循现有架构，避免无关重构。

## 11. 视觉质量约束（Visual Quality Constraints）

最终界面应体现：

- 专业的企业级软件视觉语言
- 清晰的信息层级
- 精确的网格与对齐
- 稳定一致的间距体系
- 统一的字体、颜色与组件规范
- 克制的视觉强调
- 合理的信息密度
- 精致但不过度的交互细节

严格避免：

- 大面积无意义渐变
- 过度玻璃拟态
- 多层嵌套卡片
- 厚重阴影
- 不一致的圆角
- 过多装饰性图标
- 随意使用彩色背景
- 大量无意义留白
- 过小且低对比度的文字
- 为了视觉效果牺牲业务可读性
- 所有卡片都采用完全相同的结构
- 缺乏真实业务逻辑的占位内容

## 12. 交付要求（Deliverables）

请按以下顺序完成设计任务：

1. 分析业务场景、用户角色及核心任务。
2. 确定首页信息架构和业务优先级。
3. 设计整体布局与响应式策略。
4. 建立统一的 Design Tokens。
5. 实现页面结构及可复用组件。
6. 完成必要的数据可视化与交互。
7. 补齐 Loading、Empty、Error 等状态。
8. 检查无障碍、响应式与性能。
9. 审查视觉一致性与组件复用质量。
10. 输出最终可运行的高质量界面。

如果业务背景不足，可采用合理的企业级 SaaS 工作台作为演示场景，但必须明确标记模拟数据，不得将演示内容伪装成真实业务数据。

**最终验收标准：**

用户能够快速识别关键业务状态，理解趋势，定位异常，并以较低的操作成本完成下一步任务。

设计不仅要在静态截图中精致，更要在真实数据、复杂业务、不同屏幕尺寸及各种交互状态下保持专业、一致和高效。
