# Implement UI from DESIGN.md in a GPUI project

Read this file only when `signals` reports `gpui` in `frameworks`. It replaces the web-specific parts of [implementation.md](implementation.md): the token layer (section 2 there), the browser checks (section 5 there), and the way the anti-slop check is reported (section 6 there). Composition rules, the motion spec, and the final report in that file still apply. Material rules come from the entry in `DESIGN.md`; this file only says how to write them in GPUI.

Three labels mark how far each statement was checked:

- **run**: rendered on Windows in the `bahayonghang/devsweep` material spike and measured from screenshots. The letter (A–F) names the row of the conclusions table in [devsweep#5][spike].
- **source**: the symbol was read in the GPUI source at the pinned commit. Nothing was run.
- **未验证**: neither. Treat the recipe as a starting point, run it, and report what happened.

`Last verified: <date> against <link>` gives the day a statement was checked against that source. A statement about another GPUI version is 未验证 until you probe it (section 2).

## 1. Scope and project root

- This file applies when `frameworks` contains `gpui`. It covers upstream GPUI primitives. It does not cover other native toolkits.
- The project root is the directory of the crate whose `Cargo.toml` declares the GPUI dependency. Pass that directory as `--root` to `signals`, `route`, `apply`, and `palette`. `DESIGN.md` is written there.
- In a workspace, the UI crate is often one level down. `signals` on the workspace root then reports no framework and prints a note that names the child directory. Rerun with that `--root`.
- A `design.md` in the repository root that is not a design contract (for example a product plan) is not this project's `DESIGN.md`. The UI crate directory is the root, so that file is out of scope.
- `signals` does not read Rust source. It cannot see an accent token there. Choose an airy-glass colourway with `--prompt` or `--palette`.

## 3. Token layer

1. Put every token in one Rust module (for example `src/theme.rs`). It holds one struct with two constructors, `light()` and `dark()`. Field names follow the `DESIGN.md` role names: `colors.sheet-edge` becomes `sheet_edge`. The dark constructor takes its values from the `-dark` tokens. Fonts, radii, spacing, and motion values are constants in the same module.
2. A translucent token is a colour plus an alpha. Keep them together in one type, so a fill and its alpha cannot drift apart.
3. Components take `&Tokens`. No other file contains a colour literal.
4. Switching theme swaps the token struct and calls `cx.notify()`. Follow the system appearance, and let an explicit user choice win. Following the system appearance through `observe_window_appearance` is 未验证; the spike switched with a key.
5. Read the airy-glass values from `palette --format json`, not from memory: `colors` is the light group and `dark.colors` the dark group.

Check that no colour literal lives outside the token module:

```bash
grep -rnE '0x[0-9A-Fa-f]{6,8}\b|#[0-9A-Fa-f]{6,8}\b|hsla\( *[0-9]|\b(white|black|red|green|blue|yellow|transparent_black|transparent_white)\(\)|\bopaque_grey\(' src --include='*.rs' \
  | grep -v 'src/theme.rs'
```

It finds hex literals, `hsla(` with numeric arguments, and GPUI's named colour functions. Every remaining line is a defect or a hex constant that is not a colour. Explain each one that stays. This grep is a manual check; it is not a mechanical gate (section 9). The command was run on the devsweep `desktop-gpui/src` tree, where it lists the files that hold colour literals.

Blob (A(2)). Build each `Arc<Image>` once and keep it: the cache key is a content hash, so rebuilding it per frame hashes per frame. Images decode on a background thread, so the first frame has no blobs; wait one frame before a screenshot.

```rust
fn blob_svg(tint: Tint, edge: f32) -> Arc<Image> {
    let svg = format!(
        concat!(
            r##"<svg xmlns="http://www.w3.org/2000/svg" width="256" height="256">"##,
            r##"<defs><radialGradient id="g">"##,
            r##"<stop offset="0" stop-color="#{rgb:06X}" stop-opacity="{alpha}"/>"##,
            r##"<stop offset="{edge}" stop-color="#{rgb:06X}" stop-opacity="0"/>"##,
            r##"</radialGradient></defs>"##,
            r##"<rect width="256" height="256" fill="url(#g)"/></svg>"##,
        ),
        rgb = tint.rgb, alpha = tint.alpha, edge = edge,
    );
    Arc::new(Image::from_bytes(ImageFormat::Svg, svg.into_bytes()))
}

// A zero-size anchor at the blob centre; the field positions and clips it.
div().absolute().size(px(0.0)).left(relative(x)).top(relative(y)).child(
    img(image.clone())
        .absolute().left(px(-rx)).top(px(-ry))
        .w(px(2.0 * rx)).h(px(2.0 * ry))
        .object_fit(ObjectFit::Fill),
)
```

Paper (B). `Tint` is the colour-plus-alpha type from section 3.

```rust
/// CSS `0 <y>px <blur>px <spread>px <colour>`. GPUI's blur_radius is the Gaussian sigma.
fn soft_shadow(color: Tint, y: f32, css_blur: f32, spread: f32) -> BoxShadow {
    BoxShadow {
        color: color.color().into(),
        offset: point(px(0.0), px(y)),
        blur_radius: px(css_blur / 2.0),
        spread_radius: px(spread),
        inset: false,
    }
}

/// CSS `inset 0 1px 0 <colour>`.
fn top_highlight(color: Tint) -> BoxShadow {
    BoxShadow {
        color: color.color().into(),
        offset: point(px(0.0), px(1.0)),
        blur_radius: px(0.0),
        spread_radius: px(0.0),
        inset: true,
    }
}

/// The part of an outer shadow that falls below the element's bottom edge.
fn ground_shadow(shadow: BoxShadow, radius: f32) -> Div {
    let reach = f32::from(shadow.offset.y) + 3.0 * f32::from(shadow.blur_radius);
    let drop = (1.0 - f32::from(shadow.offset.y) - f32::from(shadow.spread_radius)).max(0.0);
    div()
        .absolute().left(px(-reach - 1.0)).right(px(-reach - 1.0))
        .top(relative(1.0)).mt(px(1.0)).h(px(reach))
        .overflow_hidden()
        .child(
            div()
                .absolute().left(px(reach)).right(px(reach))
                .top(px(drop - 2.0 * reach)).h(px(2.0 * reach))
                .rounded(px(radius))
                .shadow(vec![shadow]),
        )
}

fn paper(t: &Tokens) -> Div {
    div()
        .rounded(px(SHEET_RADIUS))
        .bg(t.sheet.color())
        .border_1()
        .border_color(t.sheet_edge.color())
        .shadow(vec![top_highlight(t.sheet_highlight)])
        .child(ground_shadow(soft_shadow(t.sheet_shadow, 12.0, 40.0, -16.0), SHEET_RADIUS))
}
```

What differs from CSS (B, all **run**):

1. `blur_radius` is the Gaussian sigma. CSS `blur 40px` is sigma 20, so pass half.
2. An outer shadow is painted under the whole element, not only outside its box. Paper is translucent, so a shadow set on the paper darkens the paper (light: `#F6FCFA` became `#EFF6F5` on a small sample; larger paper darkens more).
3. When the unblurred shadow rectangle does not intersect the clip region, GPUI draws none of the shadow. `ground_shadow` therefore places the caster 5px lower than CSS for the paper shadow and 1px lower for the overlay shadow.

Also: paper must not use `overflow_hidden()`, or the shadow hanging below it is clipped; wrap the content in an inner element when it needs clipping. `ground_shadow` suits a shadow with a negative spread only. In the dark group the shadow is weak (3–7 levels per channel below the field), so paper is told from the field by its fill and edge (F).

Last verified: 2026-11-18 against [devsweep#5][spike] (rows B and F).

Motion:

- Wrap an element with `.with_animation(id, Animation::new(duration).with_easing(...), |element, delta| ...)`. Write the motion spec from [implementation.md](implementation.md) first.
- `with_animation` reads `App::reduce_motion()` itself: when the flag is set, a one-shot animation renders its end state, a repeating one renders its start state, and no frames are scheduled.
- The flag defaults to `false`, and GPUI does not set it from the operating system at `322cd509`. Read the system setting at startup and when it changes, then call `cx.set_reduce_motion(...)`. Until the application does this, "respects reduced motion" is false. Which system call to read is outside GPUI and 未验证 here.
- Focus indicators never animate. Keyboard state changes do not animate.

Last verified: 2026-11-18 against [animation.rs][g-anim] and [app.rs][g-app] (**source**; no animation was run in the spike).

## 6. Fonts and icons

- Embed the open font that the entry names. Load it once at startup: `cx.text_system().add_fonts(vec![Cow::Borrowed(include_bytes!(...))])?`. Handle the `Err`: fall back to the system UI font, and say so in the report. Then use `.font_family("<family name>")`. (D, **run**: Figtree registers under the family name `Figtree`.)
- Ship the font's licence text beside the font file, and add the font to the project's third-party notices. Do not embed a licensed brand font ([brand-boundary.md](brand-boundary.md)).
- Variable font weights snap to named instances. With the Figtree variable font, 400, 600, and 700 each render on their own, and 650 renders exactly as 700. Write the entry's 650 title role as 600, and record that in `Known Gaps`. (D, **run**)
- Tabular figures: `.font_features(FontFeatures(Arc::new(vec![("tnum".into(), 1)])))`. (D, **run**)
- Chinese text: do not embed a CJK font for this. On Windows, when a font lists fallbacks, `gpui_windows` maps those families first and then appends the system font fallback (`GetSystemFontFallback`), so glyphs missing from the Latin face come from a system font. This is **source** only. The spike window rendered Chinese labels under `Figtree`, but which face they used was not recorded, so the result is 未验证. Name preferred CJK families through `FontFallbacks` when the entry lists them (未验证).
- Icons: `svg().path("<asset path>")` or `svg().data(bytes)`, sized with `.size(px(...))` and coloured with `.text_color(...)`, so a monochrome icon follows the text colour as `currentColor` does. One set, one stroke width ([design-system-core.md](design-system-core.md), Icons). An icon-only control needs an accessible name. `svg()` was not run in the spike: 未验证.

Last verified: 2026-11-18 against [devsweep#5][spike] (row D), [text_system.rs][g-text], [direct_write.rs][g-dwrite], and [svg.rs][g-svg].

## 7. Layout

- The field is the window's first child and fills it. Papers are its siblings on top, with a gap of at least `spacing.md` between papers and between a paper and the window edge. At least two papers sit directly on the field. Paper does not nest; group content inside a paper with wells.
- Set a default size and a minimum size in `WindowOptions` (`window_bounds`, `window_min_size`). The spike used 1280×1040 logical pixels by default and a 960×600 minimum; these are its choices, not tokens.
- GPUI lengths are logical pixels. At 125% scaling a 1px border is one physical pixel (B, **run**). Other scale factors are 未验证.
- Blob centres are percentages and blob radii are fixed pixels. When the window widens from 960 to 1600, the blobs stay in their corners and the middle shows the plain gradient; nothing shifts or clips (A, **run**, measured after the resize; a continuous drag was not observed).
- Narrow window: below the width at which two papers no longer fit, stack the papers in one column and keep the gaps, so the field still shows. Choose the layout from the window's width in `render`. Set `window_min_size` no smaller than the narrowest width you have checked. The one-column layout in GPUI is 未验证.

Last verified: 2026-11-18 against [devsweep#5][spike] (rows A and B) and [platform.rs][g-platform] (`window_min_size`).

## 8. Window material

- Default: the window is `WindowBackgroundAppearance::Opaque`, and the application paints an opaque field. The material in section 4 does not depend on the system backdrop: with the field at alpha 1, none of the values below changes the interface. (E, **run**)
- The system backdrop is not where the glass look comes from. Do not use it to make paper look frosted.
- If the project still wants a backdrop, use only the public API: `WindowOptions { window_background, .. }` and `window.set_background_appearance(...)`. Do not vendor or patch a platform crate for looks.
- The public API returns nothing, so the application cannot tell whether the material took effect. Decide from conditions you can read: a composited swap chain, the system transparency setting, high contrast, the window width.
- Luminance check before shipping a backdrop: put a black surface and then a white surface behind the window and read the same field pixel on both. If the backdrop can darken the field below the contract's lightness, use `Opaque`. In the spike, `Blurred` with the light field at alpha 0.9 measured a relative luminance of 0.7184 and 0.6992 over black, against the devsweep project's own 0.70 floor. That is no margin.

Measured on Windows (E, **run**):

| Value | Result |
| --- | --- |
| `Opaque` | The field is exactly as painted. |
| `Transparent` | Plain alpha: black behind the window shows as black. |
| `Blurred` | The backdrop shows through the client area, blurred, with no tint. Still shows when the window loses focus. |
| `MicaBackdrop`, `MicaAltBackdrop` | Samples the wallpaper, not the content behind the window. Follows the system app mode, not the application's theme. Turns into a flat colour when the window loses focus. |
| `Blurred` or Mica with DirectComposition disabled | No effect: transparent areas are black. |

Under reduced transparency or system high contrast, paper and overlays use `sheet-solid` and the window is `Opaque`. GPUI has no API for either setting at `322cd509`; query the operating system. Behaviour with the system transparency setting off, and under high contrast, was not run: 未验证.

Last verified: 2026-11-18 against [devsweep#5][spike] (row E) and [platform.rs][g-platform].

## 9. Verify

These steps replace the browser steps in [implementation.md](implementation.md) section 5. Compile success is not visual verification.

1. Build and run the application.
2. Take native screenshots at the default window size and at the minimum width, once in the light group and once in the dark group: four screenshots. Wait one frame after launch, because images decode in the background.
3. When the entry ships a reference page (`assets/reference/<slug>/index.html` in the skill directory; `style:airy-glass` has one), open it in a browser at the same sizes and take the same four screenshots. Put each pair side by side and walk this list:
   - Is the field visible between the papers and at the window edge?
   - Are the blobs soft, with no hard edge, seam, or diamond shape?
   - Does each paper show its edge and its top highlight?
   - Are wells told apart by fill, with no gray outline?
   - Do inputs, checkboxes, radios, and switches have a visible boundary, and do labelled buttons have none?
   - Does text sit on paper or a well, with only `ink` on the field?
   - Does every item above hold in the dark group?

   The reference page shows the default colourway and placeholder content. Compare material and structure, not hue or copy.
4. Contrast: take the measured tables from `palette --format json` (`contrast` and `dark.contrast`). Then check that every colour in the token module equals the value in `colors` and `dark.colors`. A token that differs has no measured contrast.
5. Walk the focus order with the keyboard: every control is reached and shows the ring. Look at one hover, one disabled, and one error state.
6. Turn on the system's reduced-motion setting and look once. Turn on high contrast and look once.
