# 逆向防护

用于在行动前识别如何失败，从而设计防线；不是生成或执行破坏任务。输入为目标、方案、资源和不可接受的损失。

1. 假设目标最终失败，列 5–7 个足够具体、可以观察的致败操作或缺失环节；写出破坏机制，而非“执行力差”等标签。
2. 按破坏力和可逆性排序，同时标证据与推断。优先看单点失效、反馈太晚、不可恢复损失，不假造精确概率。
3. 逐条翻为可检查规则：谁或什么负责、何时检查、通过条件、异常信号及补救动作。
4. 点出一个最容易被忽略的风险和一项立即可做的防护，说明残余风险。

输出失败清单、优先级、防护检查表和第一步。只做预防性分析，不运行模拟破坏、删数据或绕过控制。已发生故障需要复现诊断时按意图另选方法；证据不足就用假设标记，防线达到目标后停止，不为穷举灾难扩大范围。
