# 持续教学

只有用户明确要求跨课次学习时进入；单问概念不创建课程。输入为学习目标、现有经验、时间约束和教学工作区。用户已给目录就使用；未给且当前目录是软件项目，先解决教学位置，不静默占用项目根。

进入或恢复课程时读取 [教学工作区合同](../teaching-workspace.md)，不要预读其他方法。

1. 首次先建立具体 mission：学会后能完成什么、为什么需要、约束与排除。目标不清才问；一工作区一个 mission，改变 mission 须用户确认并留学习记录。
2. resume 时读取 MISSION、RESOURCES、GLOSSARY、相关 learning-records 和 NOTES，检查已有 lessons / assets。根据已展示的能力确定下一小步，不重建课程或重讲已掌握内容。
3. 从可信资料补足课程必要知识；优先一手资料，每项有来源和用途，资源缺口明示。离线时只使用已可核对资料，不能称“已查最新来源”。现实经验可推荐可信社区，但不替用户报名、发消息或忽视其不参加的偏好。
4. 每课一个紧扣 mission 的小胜利：短 HTML 课程、必要知识、检索练习、即时反馈和迁移题；安排间隔复习，技能练习可交错。区分当场流利和长期保持，不用长讲义挤占练习。
5. 写文件前查最大编号再递增；复用共享 assets，第一课建立共享 CSS，后续按需要增加 quiz / diagram 组件。课程链接到相关 reference 和前后课；可用时实际打开检查，否则标未视觉验证。
6. 只有用户展示理解，才记录为学会并更新 glossary；自报经验标“用户自述、深度未验证”。只讲过的内容不能写成掌握。

输出课程文件、练习反馈、必要参考与下一步。目录惰性生成，普通课程文件在已授权范围内直接写，不逐个请示；不得覆盖旧课。记录是教学目录内状态，不是宿主长期 memory。用户暂停即保存真实进度，列未验证项后停止。
