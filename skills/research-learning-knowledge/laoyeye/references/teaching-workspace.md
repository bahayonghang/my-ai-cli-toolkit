# 教学工作区与四份格式

本附录仅在持续教学时读取。路径均相对用户确认的教学目录，不是 skill 包目录。一个 mission 一个工作区；检查现有文件后惰性创建，不能为了完整目录树生成空文件。

| 文件 | 内容和写入时机 |
| --- | --- |
| MISSION.md | 真实学习目的和成功表现；首次建立，目标改变经用户确认后更新 |
| RESOURCES.md | 已核对的可信知识来源、可选社区、缺口和用户社区偏好 |
| GLOSSARY.md | 用户已理解术语的紧凑定义、别名与歧义约定 |
| learning-records/0001-slug.md | 非显然理解、误解修正、先前经验或 mission 变更的证据 |
| lessons/0001-slug.html | 一课一个可练习目标的短 HTML；链接课程与参考资料 |
| reference/*.html | 可打印、可复查的压缩知识单元，不复制整份课堂叙述 |
| assets/* | 共享 CSS、测验、图示等；优先复用，确有第二处用途才扩组件 |
| NOTES.md | 用户明确表达的教学偏好、未决项、下一步；不存秘密或臆测画像 |

lessons 和 learning-records 分别扫描现有最大数字，再加一，至少四位数字；不因中间编号空缺回填覆盖，不把目录数量当最大编号。对已存在文件的修订保留原有有效内容。

## MISSION 格式

用一个主题标题和四项：为什么学（具体工作 / 生活结果，1–3 句）、成功表现（可观察能力）、约束（时间 / 预算 / 经验）、当前排除。保持短小，避免把课程计划塞进 mission。

每个新课说明如何服务成功表现。用户改变方向时先确认，再更新 mission，并写关联学习记录；不因为当前新鲜话题悄悄换目标。

## RESOURCES 格式

分 Knowledge、Wisdom / Communities、Gaps。每条知识资源写标题、作者或机构、真实链接、核对日期、可信依据和本课程何时使用。优先原始材料；不能确认链接内容就标“待核实”，不虚构书名或引文。

社区条目写适合求助的具体问题、参与方式及可见限制；推荐不等于代发、注册或付费。记录不参加社区的偏好，避免反复推荐。过期、离题或低质量资源就地修订，清楚注明未覆盖区域。

## Learning record 格式

标题后用 1–3 句写新理解及其对后续课程的影响；必要时加 Evidence（用户答案 / 作品）、Implications、Status。用户展示理解、纠正误解、披露经验、改变 mission 时才写；活动流水账、仅讲过的知识、glossary 定义不重复记录。

证据区分“当场正确应用”“延后检索通过”和“用户自报、尚未验证”。新理解推翻旧记录时，将旧记录标为 `superseded by LR-NNNN` 并互链，不删除学习历史。

## GLOSSARY 格式

主题说明后按术语列：标准名称、1–2 句定义、需避免的歧义别名。只有用户能正确使用才收录；新介绍的词先留在课程中。后续课程统一沿用术语，理解深化时修订定义，广义与本课程用法不同须标明。

## 课程质量与恢复

每课先少量知识，再做回忆和操作，以真实回答反馈；选择题避免答案长度、格式、措辞暴露正确项。至少安排一项延后复习或迁移，未运行便标计划。

resume 以 mission、记录证据和未决项确定当前水平，不因 lesson 已存在就认定已完成。交付时给实际文件链接、已验证 / 未验证状态和最小下一步；课程记录不自动写入宿主记忆。
