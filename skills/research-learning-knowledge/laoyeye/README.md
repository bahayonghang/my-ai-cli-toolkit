# laoyeye

一个入口，把问题问清、概念讲透，再选择合适的分析或决策方法。覆盖原 laoyeye 的 25 项功能入口；`matt-grill-me` 与 `matt-grilling` 共用一套正文，因此包内是 24 套方法。

本包是独立整合适配，不是 LearnPrompt 官方版本，也不是提示语原文镜像。方法正文按需读取，不必安装其他叶子技能；不会把全部内容一次塞进根入口。

## 你可以直接这样说

向已加载本包的 agent 说清目标，或直接点名原方法：

- “用 laoyeye 帮我理清这个问题，先别建议。”
- “用 laoyeye 的 matt-grill-me 拷问这个计划，先解决依赖。”
- “用双层解释讲懂幂等，联系这个支付例子。”
- “这个概念刚才还是没懂，用寓言换个方式讲。”
- “对这个行业做横纵研究，截至今天；没查到的不要当事实。”
- “比较 A 与 B 的最强理由，先问那个最关键的问题。”
- “用 laoyeye 设计一个七天实验，先只给方案。”
- “用 matt-teach 在我指定的目录持续教我 Rust，下次能接着学。”
- “把这个目标写成 agent 任务书，交付后停止。”

任务已明确时直接开始，歧义才补一个会改变方法的问题。方法名是包内选择信号，**不承诺注册或兼容旧斜杠命令**。完整方法表在 [SKILL.md](SKILL.md)。

## 本地安装与同名冲突

当前交付是仓库内的本地包；远程发布、`npx` 安装和客户端新会话发现未验证。仓库身份为 `bahayonghang/my-ai-cli-toolkit`，不要从本机文件夹名推导 GitHub 地址。

从本仓库根目录可用现有 live-link 安装器，先把目标路径替换为真实项目目录：

```powershell
python scripts/install_projects.py --skill laoyeye --project "<project-root>"
```

此命令是安装说明，本次创建不执行安装。需要能读取 `SKILL.md` 和相对 references 的 agent；联网、文件与展示工具由当前宿主提供。接口文件只是使用入口，不证明任何客户端已发现或运行。

新包和 LearnPrompt 的旧路由都叫 `laoyeye`，**同一安装目录只能选一个版本**。安装前核对现有目录归属；若安装器将覆盖同名内容，停下来由用户选择，不自动卸载、重命名或覆盖。其他旧叶子若仍安装，其 metadata 仍可能占用上下文，本包不会替用户删除它们。

## 方法与产物

| 需求 | 常见产物 |
| --- | --- |
| 澄清与拷问 | 事实 / 假设、重述问题、设计树决策与未决分支 |
| 讲解与学习 | 双层解释、自测、寓言、可打开的 HTML、持续课程 |
| 研究与方案分析 | 带来源日期的核查、时间线、横向表、条件判断与证伪点 |
| 决策 | 两边最强论证、关键问题、最小实验卡 |
| 任务书与收尾 | 可复制的惰性任务书、六面状态、实际改动与清理预览 |
| 明确的自我探索 | 经历证据链、能量地图、三个五年版本、可逆原型 |

持续教学、天赋探索、人生设计需要明确请求，不能由一句迷茫自动启动。johari / concise 只作用户开启的本会话设置，可叠加主方法，随时关闭，不自动写永久偏好。

长模式保留深度产物：研究 10,000–30,000 字、天赋说明书约 10,000 字、人生蓝图 8,000–12,000 字；用户指定长度优先，材料不足不凑字，可分段交付。普通请求不继承这些长度。

## 文件、网络和执行边界

- 一般分析只需对话；视觉讲解会在获准位置生成 HTML。持续教学使用独立、明确的工作区，保留 mission、资源、学习证据、glossary、递增课程和共享 assets，不静默占用软件项目根。
- 研究 / 核查需要实际资料；离线时交框架、待检索清单和证据缺口。私有材料不冒充外部确认；模拟专家不冒充真人参与。
- 任务书严格 compile → validate → present → stop。正文的“实施直到完成”是交付内容，不能触发 Goal、自动化、消息或执行命令；保存任务书不等于启动。
- 实验仅设计，执行要有对应授权。诊断、治理和教学的范围内操作遵守已有有效授权，不逐步重复请示；删除、跨项目编辑、外部联系和记忆写入不能随分析附送。
- 治理先审计和预览，机器生成记忆不手改。例子里的 token 占位符不是向用户索取密钥的理由。

论文精读综述、普通润色翻译、生产 UI、专业代码 diff / Trellis 规划审查及原生 Goal 管理沿用各自工作流；本包不靠宽描述抢这些任务。明确选择内部诊断或治理后，方法在包内完整执行，不转调外部叶子技能。

## 上下文与验证

一个可发现入口与方法级读取是 **design advantage**。静态字符 / bytes 的比较与确定性检查见 [context-budget.json](reports/context-budget.json) 和 [verification.md](reports/verification.md)；未跑项目标 `NOT_RUN` 或 `UNVERIFIED`。

比较必须分开三种情况：整体安装的 metadata、经路由选一个方法、直接调用旧叶子。旧叶子直达可能更省；多个方法已读入后不会自动从历史卸载。不把字符下降说成实测 token、延迟或输出质量优势，不把 schema / fixture 通过说成真实模型遵循。

维护者可离线检查包结构和预算（替换 `<skill-dir>` 为本包真实路径）：

```powershell
python "<skill-dir>/scripts/context_report.py" --output "<skill-dir>/reports/context-budget.json"
python -m unittest discover -s "<skill-dir>/tests" -p "test_*.py"
```

这些是维护命令，不是用户调用方法的前置步骤。方法运行不依赖 Python；只有维护检查需要 Python 3。

作者采用 qiaomu-meta 的设计方法。其 `validate_skill.py` 强制要求独立 manifest；本仓库以 SKILL frontmatter 为版本权威，不为迎合该外部 schema 增加 manifest。具体诊断与偏差见验证记录，不宣称该外部门禁全部通过。

## 排障与回滚 / Troubleshooting

找不到方法时先检查安装是否包含 references，以及目标链接是否仍指向本包；不要把所有正文复制到根入口补救。不能读取文件的宿主无法获得完整方法，必须明确报告。

无联网就用离线降级；未能打开 HTML 就标未视觉验证。教学恢复先核对 mission 和学习证据，不按课程文件存在推定掌握；多于两个决策选项不悄悄删成两个。

包级回滚只移除本次新增包及相应生成目录项，不碰旧安装或用户工作。课程 / 项目内容的修订保留 diff 和恢复依据，运行方法不意味着授权破坏性清场。
