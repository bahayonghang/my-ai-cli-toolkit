# 执行计划
1. 审阅两子任务规划并获得后续实施授权；当前不运行 task.py start。
2. 各子任务实施前重新核对源码、dirty 状态和审计证据。
3. 完成子任务内指定的最小修订及边界场景；按仓库约定使用实施/检查子代理。
4. 执行子任务相关测试及一次 just ci；不把静态 fixture 当作实际模型运行证据。
5. 对照 R1—R6 和每个子任务验收条件做集成审查，缺少远端证据不得称完整修复。
6. 交付具体变更和证据；提交、安装、远端处置、归档按届时授权及工作流执行。

规划检查：对父任务和两子任务分别运行 python .trellis/scripts/task.py validate <task>，确认全部 status=planning，父子链接一致，清单无种子条目，git diff --check 通过。
