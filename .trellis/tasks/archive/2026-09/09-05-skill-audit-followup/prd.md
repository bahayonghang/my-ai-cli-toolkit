# 审计遗留技能优化与发现一致性

## 目标与背景
将用户提供的审计第 4—8 节收敛为两个技能的可独立验收任务。当前仅授权创建规划；任务保持 planning，不启动、不实施、不提交、不更改安装入口。

## 需求与子任务
| ID | 需求 | 承接任务 |
| --- | --- | --- |
| R1 | 无暂存时完成只读候选清单、分组及消息草稿，保持暂存边界 | 09-05-git-commit-preparation-hook |
| R2 | Git commit hook 非零先诊断并准备精确修复，执行服从已有授权 | 09-05-git-commit-preparation-hook |
| R3 | 保留提交安全门和已授权 push/PR 交接 | 09-05-git-commit-preparation-hook |
| R4 | 核验 canonical 源、发现入口、缓存与旧项目副本；保留未迁移增量 | 09-05-goal-meta-discovery-completion |
| R5 | 完成条件为合取；缺证据或迭代耗尽不能称为完成 | 09-05-goal-meta-discovery-completion |
| R6 | 保留不启动 Goal、受控覆盖及禁止隐式外部动作的边界 | 09-05-goal-meta-discovery-completion |

## 验收
- P1：两子任务均有 PRD、design、implement 和真实上下文清单；源审计每项有归属。
- P2：实施后 R1—R6 各有行为证据；已修复行为只做回归保护，不重复重写。
- P3：本地验证、模型行为验证、远端安装/新会话验证分别报告；缺少必要证据的子任务保持未完成。
- P4：没有修改 Trellis 路由、脚本、模板、生成规则或权限模型；仓库 diff 仅含获准范围。

## 不在范围
自动暂存点名文件、新增 scoped-changes、扩大 all-changes 触发词、自动修复消息后重试、放宽旧版按类别暂停、生成后立即启动 Goal均为未批准候选。删除/改名远端旧副本、全局安装和缓存变更须另有具体目标授权。本次只规划；不将这些候选隐藏为默认实施步骤。
