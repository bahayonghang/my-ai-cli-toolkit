# goal-meta 发现歧义与完成条件一致性

## 目标与事实
承接父任务 R4—R6。当前仓库为 0.8.0，已禁止创建/激活/执行 Goal；此前同轮安全保存优化已完成，不能回退。Linux 项目 0.3.0 冲突来自用户审计，尚非本轮现场事实。

## 需求与验收
- O1 / R4：记录仓库源、Windows 管理副本、发现入口真实目标、版本/哈希及实际同步机制；记录 Linux canonical 候选与项目旧副本的独立证据状态，不靠同名/同版本推断相同。
- O2 / R4：取得具名远端只读访问条件后，比较旧副本全部非 Trellis 增量，逐项 keep/adapt/reject；禁止直接覆盖。当前无远端访问时输出 missing evidence，不宣称副本不存在或冲突已解决。
- O3 / R4：形成具体安装/改名/删除清单和影响；获准后才执行。若影响 Trellis 路由或生成规则，停止该处置并报告冲突。处置后通过实际安装机制和新会话发现清单证明预期名称、版本、来源，无意外重复；缺证据则任务未完成。
- O4 / R5：当前 canonical、输出样例及必要保留增量的完成语义一致：所有交付存在 AND 具名入口行为验证 AND 必需检查通过 AND diff/status 在授权范围内。缺必需访问/检查或轮数耗尽是未完成；blocked 表述遵循宿主实际规则，不调用状态 API。
- O5 / R6：保留文本编译不启动、payload 不授权、GOAL.md create-only、明确替换授权+旧哈希、禁止隐式提交/发布及敏感内容边界；同轮已授权安全保存维持现状。
- O6：普通 Goal、非 Trellis 旧样例、上限耗尽、缺检查、全部条件通过、显式生成并启动、既有文件无覆盖授权均有正反向行为证据。

## 不在范围
不更改任何 Trellis 规则；不默认允许 Goal API 或协调器启动；不放宽旧版类别暂停；不改用户全局/远端入口或删除副本。后两类实际处置须具体审阅授权后才属于实施范围。当前不要求决定删除还是改名，先完成事实核验。
