# design.md — persistent Goal contract

## Architecture and boundaries

This is a Governed, file-writing extension of the existing cross-platform meta
skill. Keep the public entrypoint lean and isolate judgment, deterministic
mutation, and evidence:

| Layer | Owner | Responsibility |
| --- | --- | --- |
| Routing and state transitions | `SKILL.md` | Persistence triggers; S1 remains read-only; S6 may write only an approved file |
| Persistence policy | new `references/persistent-goal-contract.md` | Root resolution, authority, schema, conflict, Git visibility, platform launch |
| Platform fact registry | `references/platform-goal-facts.md` | Dated primary-source facts and exact lifecycle vocabulary for Claude, Codex, Grok, OMP, and Kimi |
| Existing goal design | `references/default-goal-strategy.md`, `goal-command-playbook.md`, `interview-checklist.md` | Draft/final output and the transition from chat-only to persisted mode |
| Trellis adapter | `references/trellis-goal-cadence.md` | Link task artifacts and retain commit/archive gates inside the persisted contract |
| Deterministic validation | `scripts/lint_goal_command.py` | Add a persisted-contract mode without weakening existing inline checks |
| Deterministic mutation | new `scripts/persist_goal_contract.py` | Validate stdin, constrain path, conflict-check, write UTF-8/LF, report hash/status |
| Regression evidence | `tests/*.mjs`, `evals/evals.json` | Runtime helper matrix plus human-reviewed routing/output cases |
| Package metadata | `agents/interface.yaml`, category `AGENTS.md`, generated docs | Accurately advertise the optional write path and its authorization gate |

Do not edit any target platform runtime, Trellis scripts, memory stores, global
instructions, `.gitignore`, or unrelated skills.

## State flow

```text
S0 route
  -> no project or no persistence intent -> existing chat-only flow
  -> persistence intent / complex-file proposal
       -> S1 read-only root + rules + commands + git + GOAL.md state
       -> S3/S4 show contract, exact target, create/replace effect
       -> user confirms S6
       -> validate stdin and path
       -> create-only or hash-guarded replace
       -> read back + hash + git visibility
       -> return platform launch command
```

`直接给` can skip S3 only when requirements are already concrete. It cannot
turn an unmentioned write into authorization. An explicit request such as
`直接生成并保存到项目根目录 GOAL.md` covers both fast-path drafting and that
specific create action.

## Root and path contract

1. The caller supplies the literal root discovered by
   `git rev-parse --show-toplevel`. The helper resolves it and verifies the
   target is a direct child.
2. Default basename: `GOAL.md`. Optional alternate names, when the user chooses
   one after a conflict, must match a conservative basename pattern and end in
   `.md`; no separators, drive prefixes, UNC paths, `.` or `..`.
3. Refuse an existing symlink / reparse-point target. A regular existing file is
   read-only until replace authorization and an expected SHA-256 are supplied.
4. Read stdin as raw bytes, decode `utf-8-sig` strictly, and fail without a
   write on invalid input instead of trusting the Windows console text wrapper.
   Validate before mutation. Write a same-directory
   temporary file with UTF-8 and `newline="\n"`, flush/fsync, then finalize with
   no-overwrite semantics or compare-before-replace. Clean the temporary path on
   every error.
5. Return machine-readable metadata (path relative to root, action, bytes,
   SHA-256, tracked/ignored/untracked). Never print the contract body.

Use only the Python standard library. No shell redirection to a destination
file, no prompt text in argv, and no mutation beyond the selected Markdown.

## Contract schema

`GOAL.md` is an approved execution contract, not a live progress log:

```markdown
# Goal Contract: <short title>

## Contract metadata
- Status: approved
- Target platform: codex | claude | grok | omp | kimi | explicit multi-platform set
- Generated by: goal-meta-skill 0.5.0
- Project root: .
- Baseline: <branch> @ <full HEAD>; dirty paths: <bounded summary>
- Generated at: <ISO-8601 with timezone>

## Authority and startup
...

## Objective
...

## Required reading and current context
...

## Scope and boundaries
...

## Constraints
...

## Verification
...

## Iteration policy
...

## Completion conditions
1. ...

## Pause / stop conditions
...

## Launch commands
...
```

The metadata snapshot is a drift detector, not a claim that HEAD contains dirty
work. At startup the executing Agent re-runs root/branch/status checks. A changed
HEAD, changed task artifact, or contradictory latest user instruction causes a
restatement and pause/stop before risky edits; benign drift can be reported and
the user can approve regeneration.

For Trellis work, Required reading names the concrete task files. The authority
order is host/system/user and scoped project rules first, then authoritative
task/spec artifacts, then this compressed contract. `GOAL.md` never silently
overrides a newer PRD or user decision.

## Platform launch adapters

The canonical contract is platform-neutral. A renderer owns only the short
launch objective, lifecycle-management vocabulary, runtime budget syntax, and
platform-specific pause/stop semantics. Do not fork the Goal body into five
copies.

### Codex

Use a short objective that first reads `./GOAL.md`, restates the important gates,
then implements. OpenAI documentation says the `/goal` text is the first prompt
and completion criteria; it does not document automatic discovery for arbitrary
`GOAL.md` files. Do not rely on bare Goal mode activation.

### Claude Code

Prefer `@GOAL.md` so the file content is included through the documented file
reference mechanism. The goal condition must still require the executing Claude
to restate completion evidence in the transcript because the independent goal
evaluator does not read files or run commands. Retain the soft turn/time bound
and stop-and-report semantics.

### Grok Build

Use an explicit `read ./GOAL.md` objective. Grok `/goal` supports
`status/pause/resume/clear`, optional `--budget <tokens>`, and an independent
evidence review before completion. Add a runtime token budget only when the
user explicitly requests it. Goal mode may be disabled for the session; report
that prerequisite rather than pretending the text enables it. Ordinary Grok
prompts support `@path`, but `@GOAL.md` inside `/goal` stays an optional,
provider-test-gated optimization.

### Oh My Pi (OMP)

Use an explicit `read ./GOAL.md` objective. OMP preserves the full objective
and exposes `/goal set/show/pause/resume/drop/budget`; `/guided-goal` is a
separate intake path. Goal mode requires `goal.enabled` and is mutually
exclusive with plan/vibe modes. The contract should require current-repository
evidence before completion and must state that budget exhaustion is not
completion. OMP's documented `@path` expansion applies inside discovered
context files, not as proof of prompt-level file attachment.

### Kimi Code

Use an explicit `read ./GOAL.md` objective until combined `@GOAL.md` + `/goal`
has provider-backed proof. Kimi limits objectives to 4,000 characters and uses
`status/pause/resume/cancel/replace/next`; its states are active, paused,
blocked, and complete. Stop limits belong in the objective for the TUI command
surface. Headless `kimi -p "/goal ..."` supports creation only and returns
distinct exit codes for complete, blocked, and paused, so it is a separate
renderer rather than a management-command fallback.

### Cross-platform fallback

When file-reference behavior is unavailable, undocumented inside `/goal`, or
the platform is ambiguous, use explicit natural language: `First read and
follow ./GOAL.md ...`. Mark provider execution as missing evidence until a real
fresh-session test proves the path. If the platform itself is ambiguous, ask or
include it in the existing bounded adjustment block; do not emit a blended
management command.

### Renderer contract

| Platform | Start | Management vocabulary | Length policy |
| --- | --- | --- | --- |
| Codex | `/goal <objective>` | view/edit/pause/resume/clear | official 4,000 |
| Claude Code | `/goal <condition>` | view/clear; no pause/resume | official 4,000 |
| Grok Build | `/goal <objective> [--budget N]` | status/pause/resume/clear | skill-owned 4,000; platform limit not found |
| OMP | `/goal <objective>` | set/show/pause/resume/drop/budget | skill-owned 4,000; platform limit not found |
| Kimi Code | `/goal <objective>` | status/pause/resume/cancel/replace/next | official 4,000 |

Extend the linter platform enum to
`codex|claude|grok|omp|kimi|both|all`. Keep `both` as the backwards-compatible
Codex+Claude aggregate; use `all` only for explicit five-platform fixtures.
Platform-specific linting rejects management-command borrowing and uses factual
error text. The generic 4,000 check remains conservative, but for Grok/OMP its
message says `goal-meta portability limit`, not `platform cap`.

## Git visibility and portability

- After write, query `git ls-files --error-unmatch`, `git check-ignore`, and
  status without mutating Git. Report one of tracked / ignored / untracked.
- Same-worktree continuation works with an untracked file.
- Other worktrees, cloud environments, teammates, or clones only receive the
  file if the user deliberately commits, copies, or otherwise exposes it there.
- The helper and skill never decide that tracking policy for the user.
- A single root `GOAL.md` assumes one active goal per worktree. Parallel goals
  should use separate worktrees, matching official Codex guidance, or an
  explicitly user-chosen alternate basename.

## Secret and trust boundary

Block representative high-confidence secret values before write: OpenAI-style
keys, GitHub PAT shapes, PEM private-key blocks, bearer/cookie/token assignments.
Do not block variable names such as `OPENAI_API_KEY` or instructions that say to
pause when credentials are required. The error reports category and line number,
not the matching secret.

The detector is a backstop, not proof that content is non-sensitive. The skill
must also tell the author not to copy `.env`, credentials, private customer data,
or raw session transcripts into the contract.

## Compatibility and migration

- Existing inline `/goal` output stays valid.
- Existing `.planning/goal-<slug>.md` requests remain honored when the user names
  that path. The new recommended persistent handoff path is root `GOAL.md`; do
  not silently migrate or delete older files.
- Keep existing Claude/Codex behavior, `both` CLI compatibility, 4k rules,
  Chinese companion titles, S6 field map, Trellis adapter, and ids 1-18.
- Add explicit host/name aliases for Grok Build (`grok`, `xAI`), Oh My Pi
  (`omp`, `Oh My Pi`), and Kimi Code (`kimi`, `Kimi Code`, `Kimi CLI`) without
  expanding the skill into unrelated plan-mode or sub-agent orchestration.
- Bump to `0.5.0`; update catalog metadata via `just docs-sync`.
- `allowed-tools` may remain the current narrow command family because the new
  mutation is through the named Python helper. Update docs/tests so they no
  longer describe the whole skill as read-only. Do not add broad `Bash` or Git
  mutation permissions.

## Failure behavior

| Failure | Required result |
| --- | --- |
| Root cannot be established | No write; ask for the project root |
| Target exists without replace authorization | No write; report hash/status and ask |
| Expected hash differs | No write; report concurrent/stale conflict |
| Target is symlink/reparse or escapes root | No write; fail closed |
| Contract lint or secret backstop fails | No write; report category without body/secret |
| Temp/finalize/readback fails | Preserve old file; clean temp; report exact stage |
| Final path is untracked/ignored | Success, but report portability limitation |
| Provider cannot read file in fresh session | Keep `UNVERIFIED`; use explicit fallback or revise adapter |
| Goal runtime is disabled or conflicts with another mode | No false start claim; report the exact platform prerequisite and preserve the file |
| Platform is ambiguous | No blended lifecycle syntax; ask through the bounded platform choice |

## Tradeoffs and rejected designs

- **Root `GOAL.md` vs `.planning/goal-<slug>.md`:** root wins discoverability and
  user ergonomics; it creates Git noise and a singleton collision, so tracking
  is reported and overwrite is fail-closed.
- **One file vs `.goal-task/<slug>/` state bundle:** one file matches the user's
  handoff need and current skill scope. A state/todo/design/lessons directory
  duplicates Trellis and turns the skill into orchestration infrastructure.
- **Explicit pointer vs persistent rule/context import:** explicit pointer avoids
  injecting task-specific instructions through AGENTS/CLAUDE, `.grok/rules`, or
  `.omp` context into every session and is portable. It is not automatic, so
  the launch command must be precise.
- **Helper vs native Write tool:** the helper earns its cost by enforcing root
  containment, conflict/hash policy, encoding, no body echo, and repeatable tests
  without adding broad tool grants.
- **Immutable contract vs live progress log:** immutable approved scope is easier
  to audit. Progress belongs in Trellis/task artifacts or another earned system.
- **One renderer vs five thin adapters:** one universal renderer would silently
  invent commands such as `clear`, `drop`, `cancel`, or `budget` on the wrong
  platform. Thin adapters preserve one contract while keeping lifecycle facts
  testable and replaceable.

## Rollback

Implementation rollback reverts the skill/package/docs changes. Runtime
rollback is explicit: a newly created `GOAL.md` may be removed only with user
authorization; a replaced file is restored from its authoritative Git/history
source or user-provided prior content. The helper never auto-deletes or hides a
material file.
